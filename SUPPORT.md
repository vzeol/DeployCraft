# Getting help

DeployCraft is maintained as an open-source project. Help is provided as time permits; there is no guaranteed
response time or service agreement. Questions and reports are welcome in English or French.

## Choose the right channel

- **Usage or setup question:** use the [question form](https://github.com/vzeol/DeployCraft/issues/new?template=question.yml).
- **Something does not work:** use the [bug form](https://github.com/vzeol/DeployCraft/issues/new?template=bug.yml).
- **Feature request:** use the [improvement form](https://github.com/vzeol/DeployCraft/issues/new?template=idea.yml).
- **Security vulnerability:** report it privately as explained in [SECURITY.md](SECURITY.md), never in a public issue.

Search [existing issues](https://github.com/vzeol/DeployCraft/issues) first. Read the installation and first
deployment steps in the [README](README.md), or use the console's built-in help (F1).

## Versions and updates

Use the [latest stable release](https://github.com/vzeol/DeployCraft/releases/latest) for normal use. Only the
latest stable release receives fixes; older releases do not have a separate maintenance branch. If a problem
occurs on an older version, check whether it still occurs on the latest stable version in an isolated test setup.

[Pre-releases](https://github.com/vzeol/DeployCraft/releases) have a **Pre-release** label and a version such as
`1.1.0-rc.1`. They are intended for testing upcoming changes. When reporting a preview problem, include the exact
preview version. The console's stable update notification does not offer pre-releases automatically.

## Include enough information

State the DeployCraft version (Help > About), Windows version, what you tried and what you expected. For a bug,
give short reproduction steps and the exact error. A small, sanitized example is more useful than a full export
of a real environment.

Issues and attachments are public. Remove passwords, tokens, account names, domain names, server and computer
names, addresses and other private information from text, logs and screenshots before posting. Use placeholders
such as `DOMAINE.LOCAL`, `SERVEUR-01` and `PC-TEST-01`. Never send a database or real deployment credentials.

Try suggested deployment steps on an isolated instance and an agreed test computer first. A support reply does
not authorize changes to a production fleet.
